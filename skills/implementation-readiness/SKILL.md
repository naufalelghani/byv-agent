# Implementation Readiness

Use this skill before substantial implementation or when a plan contains unresolved dependencies.

## Workflow
1. Review the requirements, architecture, repository instructions, current state, and proposed task breakdown.
2. Confirm scope, acceptance criteria, key design/API/data decisions, dependencies, ownership, and expected verification.
3. Surface blockers, unresolved questions, external assumptions, migration or rollout risks, and decisions that need stakeholder input.
4. Distinguish true blockers from decisions that can safely be deferred with explicit defaults.
5. Recommend a readiness status and the smallest next action to remove each blocker.

## Output
Provide a brief readiness checklist with status, evidence, blockers, assumptions, and next steps. Do not manufacture approvals or treat unanswered high-impact questions as settled.
