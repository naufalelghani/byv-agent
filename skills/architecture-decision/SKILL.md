# Architecture Decision

Use this skill when a choice affects system boundaries, data flow, persistence, APIs, security, scaling, or long-term maintainability.

## Workflow

1. Inspect the existing codebase, conventions, and project constraints first.
2. Define the decision and the criteria that matter to this project.
3. Present viable options, including keeping the current approach when reasonable.
4. Compare trade-offs: complexity, reliability, security, performance, cost, developer experience, and migration impact.
5. Prefer the smallest design that satisfies the requirements and fits existing architecture.
6. Ground claims about frameworks, libraries, and APIs in current official documentation or reputable evidence; use web search when needed.
7. Record the selected approach, rationale, rejected alternatives, consequences, and migration notes.

## Output

Use a lightweight decision record:
- Context
- Decision
- Alternatives and trade-offs
- Consequences / risks
- Follow-up actions

Do not introduce technology or architectural patterns merely because they are fashionable. Do not treat assumptions as confirmed facts.
