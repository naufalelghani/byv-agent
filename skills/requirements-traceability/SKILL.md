# Requirements Traceability

Use this skill when planning a feature, reviewing scope, or preparing acceptance validation.

## Workflow
1. Read source-of-truth requirements, repository guidance, and the current change request; resolve conflicts by asking rather than inventing.
2. Extract atomic requirements with stable IDs where practical. Separate functional, non-functional, security, usability, and operational needs.
3. Map each requirement to its implementation area, acceptance criterion, and verification method (test, inspection, or stakeholder confirmation).
4. Identify ambiguous, conflicting, missing, or untestable requirements; record assumptions explicitly and seek confirmation for material ones.
5. Check that planned tasks and tests cover each requirement and that scope changes are reflected in the mapping.

## Output
Provide a concise traceability matrix and list gaps, assumptions, and decisions needed. Do not mark a requirement satisfied without evidence. Avoid duplicating full requirements documents; link or reference their source.
